# Known Limitations — Sprint 3

Зафиксированные ограничения и технический долг по итогам Sprint 3.

---

## Аутентификация и сессии

### 1. Login не проверяет `users.status = active`

**Описание:** `auth.Service.Login` создаёт сессию для любого `user_id`, не проверяя,
является ли пользователь активным (поле `users.status` или аналог).

**Риск:** Заблокированный / удалённый пользователь может получить валидный токен.

**Решение:** В Sprint 4 добавить `UserRepository.FindByID` и проверку статуса при Login.

---

### 2. Нет refresh-токена для device_id (device binding)

**Описание:** `AuthSession.DeviceID` сохраняется, но не используется при Refresh и Logout.
Одна сессия может использоваться с любого устройства.

**Риск:** При компрометации refresh-токена атакующий может выдавать себя за устройство.

**Решение:** Добавить проверку `device_id` при ротации токена (опционально, Sprint 4+).

---

### 3. Нет rate-limiting на `/api/v1/auth/login`

**Описание:** Endpoint логина не защищён от брутфорса.

**Риск:** Перебор `user_id` возможен без ограничений.

**Решение:** Добавить rate-limiting middleware (например, по IP) в Sprint 4.

---

### 4. JWT secret хранится в конфиг-файле открытым текстом

**Описание:** `jwt.secret` в YAML-конфигах не зашифрован.

**Риск:** Компрометация конфиг-файла раскрывает секрет.

**Решение:** Перейти на vault / environment secrets в продакшн-конфигурации.

---

## Мобильный клиент (Capacitor)

### 5. Biometric auth недоступна в симуляторе без настройки

**Описание:** В iOS Simulator биометрика (`Face ID`) отключена по умолчанию.
Нужно вручную включить через **Features → Face ID → Enrolled** в Xcode.
Для работы требуется установленный код-пароль устройства.

**Риск:** Функциональность нельзя протестировать на свежем симуляторе без ручных настроек.

**Решение:** Задокументировано в `mobile/README.md`. На реальном устройстве работает корректно.

---

### 6. Мобильный клиент использует `user_id` вместо логина/пароля

**Описание:** Экран Login принимает `user_id` напрямую (UUID) без пароля.
Это dev-режим для smoke-тестирования.

**Риск:** Не подходит для продакшн.

**Решение:** В Sprint 4 добавить реальную аутентификацию (login/password или OAuth).

---

### 7. CORS в main-service разрешает `*` (все origins)

**Описание:** `corsMiddleware` в `internal/app/mainservice/app.go` устанавливает
`Access-Control-Allow-Origin: *` для упрощения разработки.

**Риск:** В продакшн не допускается wildcard origin для authenticated endpoints.

**Решение:** Заменить на явный список разрешённых origins (Capacitor scheme + prod domain).

---

### 8. `@capacitor/preferences` не шифрует данные на Android

**Описание:** На iOS `@capacitor/preferences` использует Keychain (зашифровано системой).
На Android данные хранятся в `SharedPreferences`, которые шифруются только при включённом
Full Disk Encryption или через EncryptedSharedPreferences.

**Риск:** На рутованных Android-устройствах refresh-токен может быть извлечён.

**Решение:** Для Android использовать `EncryptedSharedPreferences` или Android Keystore напрямую.
Актуально при добавлении Android-платформы в Sprint 4+.

---

## Инфраструктура

### 9. Единая БД для всех сервисов

**Описание:** `auth-proxy`, `main-service`, `notification-worker` и `message-expirer`
подключаются к одной PostgreSQL базе данных.

**Риск:** Отсутствует изоляция данных между сервисами; любой сервис имеет доступ ко всем таблицам.

**Решение:** В будущем разделить схемы или базы данных по сервисам. Текущий подход приемлем для monorepo MVP.

---

### 10. `task build` собирает только `main-service`

**Описание:** В `Taskfile.yml` задача `build` включает только `cmd/main-service`.
`auth-proxy`, `notification-worker`, `message-expirer` не покрыты.

**Решение:** Обновить `task build` для сборки всех бинарей (Sprint 4).
